# 원본 녹음으로 1.5초 채우기 — 조사와 새 데이터

2026-11-11, 한국 시간 기준. 사용자 요청에 따라 더미 노트북, 프로젝트 PDF, 강의 PDF,
현재 전처리 코드와 실제 원본 파일을 조사했다. 기존 원본과 검수본은 보존했다.

**후속 확정:** 사용자가 "충분한 원본은 연속 1.5초, 짧은 원본은 전체를 남기고 부족한 길이만
0 패딩"을 선택했다. 이에 따라 `datasets/task2/real-context-1p5-v1/`에 1,015개 전체를
생성했다. 새 설정은 `configs/task2_real_context.json`이다. 아래 후보본과 선택 대기 설명은
이 결정 이전의 조사 기록이며, 현재 짧은 파일의 정책은 `zero`로 확정되어 있다.

전체 데이터 검증은 [full_dataset_audit.json](full_dataset_audit.json), 기존 재현 도구로
1,015개를 다시 생성한 해시 검증은 [full_dataset_replay.json](full_dataset_replay.json)에 있다.
원본 구간과 기록된 gain·0 패딩으로 복원한 PCM이 모든 출력과 일치한다. 전체 테스트는
47개 통과했다. 원본·기존 검수본·라벨·화자·split은 보존했으며, CV와 학습은 아직 실행하지 않았다.

전체 원본 구간을 더 포함하면서 피크 상한을 넘는 6개 파일은 전체 gain을 낮췄다. 기존 후보의
2개 외에 `대기/spk04_008`, `대기/spk05_015`, `오른쪽/spk05_076`, `전진/spk05_143`이
추가됐다. 위치와 적용 gain은 전체 감사 기록에 남겼다. 새 주변음의 청취 검수는 아직 하지 않았다.

**조사 결론:** 제공 더미코드의 동작은 원본이 충분히 길면 실제 녹음에서 1.5초를 자르고,
원본 자체가 짧을 때만 0값 패딩을 넣는 방식이다. 모든 파일을 실제 녹음 소리로 1.5초
채워야 한다는 요구는 확인하지 못했다. 다만 기존 개인 VAD 전처리는 원본이 충분히 길어도
발화 주변만 먼저 잘라서 패딩했으므로, 가능한 경우 주변 녹음까지 활용하려는 현재 사용자
의도와 다르다. 새로운 의도는 기존 버전과 분리하여 구현한다.

**실제 원본의 길이 제한**

전체 1,015개 중 665개는 원본의 연속된 24,000샘플을 확보할 수 있다. 나머지 350개는
원본 WAV 자체가 약 1.067~1.493초다. importer에는 자르기/속도 변환 명령이 없고,
세 화자의 짧은 사례에서 원본 M4A의 재생 시간도 1.5초 미만임을 확인했다. 모든 M4A의
해시가 수집 metadata와 일치한다. WAV 변환 중 임의로 짧게 잘랐다는 근거는 없다.

| 화자 묶음 | 전체 | 원본의 연속 1.5초 확보 가능 | 원본 자체가 짧음 |
|---|---:|---:|---:|
| spk01 (기존 test) | 203 | 124 | 79 |
| spk02 | 203 | 203 | 0 |
| spk03 | 203 | 203 | 0 |
| spk04 | 203 | 85 | 118 |
| spk05 (기존 validation) | 203 | 50 | 153 |
| 합계 | 1,015 | 665 | 350 |

원본 길이/파형 규격 검사는 test 예측이나 모델 평가가 아니다. 기존 test 점수는 사용하지
않았고 새 모델 평가도 수행하지 않았다. 짧은 파일 350개를 단순히 제외하면 특히 spk05의
구성이 크게 바뀌므로, 현재 후보 665개만으로 학습·평가를 시작하지 않는다.

**짧은 원본 350개의 선택지 — 조사 당시 비교**

| 방식 | 장점 | 제한 |
|---|---|---|
| 같은 파일의 비발화 배경음을 반복해 채움 | 전체 길이를 녹음된 소리로 채우면서 라벨·화자·파일 수 유지 | 연속 녹음이 아니라 합성 패딩. 비발화 구간 검수, 반복/연결 흔적 확인이 필요. 같은 파일에 쓸 만한 배경음이 없으면 별도 처리 필요. |
| 이 파일들은 0값 패딩 유지 | 단어를 보존하고 재현이 간단함 | 전체 구간을 실제 배경음으로 채우려는 목표를 충족하지 못함. |
| 재녹음 대상으로 표시 | 실제로 연속된 1.5초 이상을 확보 가능 | 추가 수집이 필요하고 발음·환경·세션 변화가 함께 생김. 재녹음 목록을 표시하는 것만으로 완성된 데이터가 되지는 않음. |

조사 당시 사용자는 각 방식의 장단점을 요청하여 선택을 보류했다. 이후 0 패딩을 선택했으므로
짧은 원본 전체를 사용하고 부족한 길이만 0으로 채웠다. 반복 배경음 생성과 파일 제외는 하지 않았다.

**생성한 665개 후보본**

로컬 경로: `processed_datasets/real-context-1p5-candidates-v1/`.
이 경로는 Git에서 제외된다. 재현 코드는 [real_context.py](../../preprocessing/real_context.py).

- 기존 검수 crop 전체와 여유 구간을 포함하도록 원본에서 연속 1.5초를 선택했다.
- 기존 0값 패딩 위치에 해당하는 만큼 원본 주변음을 확장하고, 원본 경계에 닿으면 창을 이동했다.
- 인공 무음, 배경음 반복, 속도 변환을 추가하지 않았다. 원본 자체의 0값 샘플은 보존한다.
- 기존 gain을 유지하되 새 주변음 때문에 -1 dBFS 상한을 넘는 두 파일은 전체 gain을 낮추고
  검수 대상으로 기록했다. silence의 gain은 0 dB를 유지했다.
- 기존 crop이 이미 1.5초였던 32개는 파일 해시까지 동일하다. 여기에는 긴 단어 17개와
  silence 15개가 포함된다. 나머지 633개는 주변 실제 녹음이 확장됐다.
- `candidate_metadata.csv`는 665개 목록이다. 전체 학습용 `metadata.csv`는 만들지 않았다.
  기존 학습 설정의 데이터 경로도 바꾸지 않았다.

새 주변음으로 gain을 낮춘 검수 대상:

| 파일 | 기존 gain | 후보 gain |
|---|---:|---:|
| `audio/대기/spk04_003.wav` | +10.882 dB | -0.734 dB |
| `audio/출발/spk05_174.wav` | +6.215 dB | +5.429 dB |

청취 검수가 완료됐다고 주장하지 않는다. 특히 확장된 주변에 들어온 큰 소리가 발화와
무관한 충격음인지 확인할 필요가 있다. 위 gain 조정으로 기존 구간의 샘플 위치와 내용은
보존되지만 해당 두 파일의 진폭은 이전 버전과 다르다.

재현 명령:

```bash
.venv/bin/python -m preprocessing.real_context \
  --raw-root datasets/task2/raw-v1 \
  --reviewed-root datasets/task2/fixed-1p5-v1 \
  --output-root processed_datasets/real-context-1p5-candidates-v1
```

이미 출력 폴더가 있으면 덮어쓰지 않고 중단한다. 재실행은 새 출력 폴더를 사용한다.

**검증과 기록**

- 원본 WAV 1,015개와 기존 검수 WAV 1,015개의 기록된 해시를 생성 전후 확인했다.
- 원본 M4A 1,015개와 원본 ZIP 해시가 기존 기록과 일치한다.
- 후보 665개 모두 mono PCM16 / 16 kHz / 24,000샘플이고, 선택한 원본 연속 구간에
  기록된 gain을 적용한 PCM과 샘플 단위로 일치한다. 최대 PCM 오차는 0이다.
- 신규 검증 5개를 포함해 전체 `pytest` 44개 통과. 경계 이동, 검수 구간 보존, 원본 변경
  감지, 짧은 파일 보류, 피크 처리, 기존 선택본·silence 보존을 확인했다.
- 전체 파일 계획은 [source_audit.csv](source_audit.csv), 실행 검증은
  [execution_audit.json](execution_audit.json), 생성 요약은
  [candidate_manifest.json](candidate_manifest.json)에 보관했다.

학습/CV/특징 재추출은 수행하지 않았다. 새 데이터 버전의 기술 검증을 마쳤으며, 주변음과
피크 예외를 검수한 뒤 같은 데이터에서 세트 0·4의 증강 없는 CV부터 다시 측정한다.
기존 `auxiliary-v1`의 결과와 캐시는 그대로 보존한다.
