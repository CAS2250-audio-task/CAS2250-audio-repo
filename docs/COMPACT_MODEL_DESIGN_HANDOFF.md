# Compact 모델 병합 전달: 풀링 비교, 주파수축 가설, 보조 음향 경로

## 전달할 결정

현재 채택 구조는 **기존 넓은 시간 범위 CNN + 약0.245초 중간 특징 전달(local)**이다. Mean/Pooled/Self 세 head를 유지한다. CPU latency는 모델 선택 기준에서 제외한다. 추론 지연 자체는 중요하므로 GPU 연산과 음향 특징 추출까지 포함한 실제 처리시간을 별도로 기록한다. LR/batch 탐색은 아직 하지 않았다.

이 문서는 확인된 결과, 그 결과에 대한 가설, 별도 실험으로 검증할 내용을 구분한다. 기록된 모델 선택은 개발 검증에서 이루어졌고 독립 test 성능을 뜻하지 않는다.

## 1. Mean은 어텐션이 없는 시간 평균이다

- Mean: 각 시간 위치의 최종32D 특징을 같은 가중치로 평균.
- Pooled: 전체 시간 평균에서 입력 의존 query를 만들고 학습된 시간 가중치로 집계하는 단일 head 구조.
- Self: 위치인코딩·CLS·2head self-attention·FFN을 포함한1블록 구조.

Mean도 앞단 CNN에서 시간 문맥을 학습한다. 시간 평균만 보고 문맥을 전혀 사용하지 않는 모델이라고 부르면 안 된다. 또한 동일한 CNN 구조/초기값에서 출발했지만 모델별 CNN 가중치는 독립 학습됐다. checkpoint 선택 epoch도 다르다. 따라서 아래 차이는 완성 모델 간 비교이며 어텐션만의 순수 인과효과가 아니다.

## 2. 실제 비교: 원본에서는 어텐션의 정답률이 높지만 소음에서는 다르다

화자03, local 구조, 소음+화자 SupCon,seed42. Mean806/Pooled565/Self508epoch의 고정0dB draw0 최고 checkpoint를 비교했다. 원본203개, 추가잡음0dB는203녹음×8소음×3draw=4872조건. 4872개의 독립 녹음은 아니다.

| 지표 | Mean | Pooled | Self |
|---|---:|---:|---:|
| 원본 정답률 | 92.61% | 95.07% | 96.06% |
| 원본 macro F1 | 91.97% | 95.42% | 96.30% |
| 0dB 정답률 | 87.46% | 86.64% | 86.15% |
| 0dB 전체11종 macro F1 | 85.44% | 86.77% | 85.55% |
| 0dB 명령어10종 평균F1 | 87.99% | 86.49% | 86.15% |
| 0dB silence F1 | 59.94% | 89.55% | 79.60% |
| 명령어→silence 오답/4800 | 98 | 8 | 34 |
| silence→명령어 오답/72 | 1 | 7 | 4 |
| 별도 잡음 단독 오반응 | 4.58% | 11.88% | 12.08% |

명령어10종 F1은 동일11클래스 혼동행렬에서 silence 항목만 F1 평균에서 제외한 값이다. silence로 잘못 예측한 명령어 오답을 제거한10클래스 재평가는 아니다. 전체 F1은 각noise/draw별 macro F1의 평균이다.

**주의할 해석:** Pooled의 전체macro F1이 높다고 명령어 구별이 전반적으로 좋아졌다고 해석하면 안 된다. 이번 점수 상승은 silence F1 상승에 크게 의존한다. Mean은 명령어를 silence로 잘못 보내는 경우가 많고, 어텐션 모델은 별도 잡음 단독 입력에서 오반응이 더 많다. 정답률과 macro F1의 순위가 다르다.

### 원본 Mean 91.97%의 선택 효과

학습 중 원본 F1 최고점은 Mean95.92%(605epoch),Pooled96.35%(587),Self97.32%(301)였다. 현재 표는 원본 최고점이 아니라 소음 검증 최고점으로 선택한 checkpoint의 원본 점수다. Mean의91.97%를 평균 풀링의 고정된 성능 한계로 해석하지 않는다. 이 원본 최고점 역시 같은 개발검증에서 사후 선택한 수치다.

## 4. 세로=주파수축 도입을 기대한 이유

현재 basic CNN의 입력은[B,64mel,T]다. depthwise Conv1d는 시간 방향으로 동작하고1×1 Conv1d가 입력 주파수 채널들을 섞는다. 주파수 정보를 무시하는 모델은 아니지만, 이웃한 주파수 대역을 따라 필터를 이동시키는 연산은 없다. 첫 채널 혼합 이후의 hidden 채널은 실제 mel 주파수 위치와 동일하지 않다.

따라서 주파수축이 명시적으로 남아 있는 입력 근처에서 다음을 검증하려 했다.

| 변경 | 기대하는 역할 | 남는 위험/한계 |
|---|---|---|
| 주파수 방향 CNN | 이웃 대역의 형태/관계를 특징으로 추출 | 시간 변화까지 필요할 수 있고, 커널/정규화/용량 효과와 구분 필요 |
| 주파수 게이트/가중치 | 입력에 따라 대역별 비중 조절 | 유효 발화 대역을 약화하거나 소음 대역을 강조할 수 있음 |
| 주파수 self-attention | 떨어진 대역 사이의 관계 학습 | 계산량/일반화 검증 필요; CNN hidden-channel attention과 구분 |

주파수 CNN은 구별할 특징을 만들고, 주파수 어텐션은 관계와 비중을 학습하도록 돕는다는 설계 가설이다. 작은 발음 차이의 보존을 기대하지만 해당 오답 개선을 보장하지 않는다. mel 특징 생성 단계에서 이미 없어진 정보를 후단 블록이 복원한다고 주장하지 않는다.

선행 근거: [BC-ResNet](https://www.isca-archive.org/interspeech_2021/kim21l_interspeech.html)은 주파수와 시간 방향 연산을 결합하는 경량KWS 구조다. [FCA-Net](https://arxiv.org/abs/2407.19834)은 소음KWS의 주파수/채널 어텐션을 연구한다. 이 연구의 결과를 우리 한국어 데이터 성능으로 옮겨 주장하지 않는다.

### 병합된 주파수 실험 코드와의 관계

기준 `compact-pooling-v1`의b00956b에는 `experiments/frequency_local/`이 이미 포함돼 있다. 그 코드가 정의한 비교는 CNN basic/lowcost/frequency × 세로self-attention off/on × Mean/Pooled/Self=18조건이며 기존basic/off3개 결과를 재사용한다. 문서/코드의 존재를 학습 완료나 성능 개선 증거로 취급하지 않는다. 다른 서버의 실제 진행/완료 상태를 확인해야 한다.

lowcost는3×3 전처리 두 층 때문에 시간 support도4프레임 늘어난다(최종109→113,중간23→27). 그러므로 결과가 좋아져도 순수 주파수 처리 효과라고 단정할 수 없다. frequency CNN은 주파수축을 유지하는 F/T 연산을 사용한다. 세로 self-attention은64주파수 token을 시간프레임별로 처리하며 입력 주파수축이 섞이기 전에 둔다.

대화에서 제안했던 주파수5×시간1 필터는 시간 support를 유지해 비교하기 위한 예시였다. 현재 구현된lowcost가 그 예시와 같다고 인용하지 않는다.

## 5. 현재 이 브랜치의 보조 음향 실험은 별도 축이다

`experiment/compact-local-acoustic-aux`는 원격compact-pooling-v1 @b00956b에서 분기했다. 주파수실험코드는 포함하되 이번 실행에는 켜지 않았다. **basic local의 세 readout에 기존set3 음향 보조 경로만 추가**한다.

- 실제 입력 파형에서 포먼트F1/F2/F3와 대역폭B1/B2/B3 및6개측정가능채널을 추출한다. 여기서포먼트F1은Hz의 첫포먼트이며 분류지표macro F1과 다르다.
- 원본/추가소음 view마다 각자의 파형에서 추출한다. noisy 입력에 원본의 깨끗한 보조 특징을 대신 주지 않는다.
- train609개 원본의 유효프레임만으로 scaler를 적합하고 checkpoint buffer에 저장한다. validation/test는 scaler 적합에 사용하지 않는다.
- CNN12→16→32→32,kernel5/5/1,151프레임 유지. 기존 최종32D 특징에 residual을 더한다. 마지막 projection은0초기화하여 초기출력은local과 같다. 모델당4,720파라미터 증가.
- 이것은 별도 정답을 예측하는 보조손실/멀티태스크가 아니라 **보조입력의 특징 결합**이다. CE+0.1 SupCon same_command는 그대로 유지한다.
- 화자03/seed42/1000epoch/기존LR·batch·증강으로 실행 중이다. 예상 효과는 아직 결과로 확인하지 않았다.
- 보조 특징도 잡음에서 오측정될 수 있다. availability는 측정 성공/실패의 표시이며 정답이나 신뢰도 보장이 아니다. 추론 시 특징 추출 비용도 포함해야 한다.

## 6. 병합 후 결과를 판단할 기준

1. Mean/Pooled/Self를 유지하고 original/0dB 정답률과 전체macro F1을 함께 본다.
2. 명령어10종 평균F1, silence의precision/recall/F1, 명령어→silence 및 잡음단독 오반응을 분리한다.
3. 정지↔전진, 후진의 예측 분포, 재시작→시작, 녹음별 개선/새오답, 소음별 결과를 비교한다. 개선·악화를 모두 보존한다.
4. 주파수구조만/보조입력만의 결과를 먼저 확보한다. 둘 다 결합한 효과는 두 단일변경의 이득을 단순 합산해 주장하지 않는다.
5. 동일한 개발검증을 반복 확인한 한화자·한seed 결과만으로 일반성을 결론내리지 않는다. 다른 화자/seed에서 확인하고 독립test와 개발결과를 구분한다.
6. 성능 차이가 어텐션·음향지식만의 효과인지 확인하려면 CNN고정 head비교/추가용량을 맞춘 대조 등 별도 실험이 필요하다. 이 추가 실험들은 아직 실행하지 않았다.

실행 중인 학습의 source/protocol을 바꾸지 않고 문서만 추가했다. 이후 병합 시 대상 브랜치의 최신 진행 상태로 실행 여부를 갱신한다.

증강에관한기존설정과결과는 [증강실험기록](AUGMENTATION_HISTORY.md)을함께확인한다.
